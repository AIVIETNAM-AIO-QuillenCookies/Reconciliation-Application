# Structural refactoring report — 2026-11-15

This report records a **behavior-preserving** cleanup of the module structure. No calculation, accounting rule, SQL text, UI text or markup, stylesheet, route, store contract, exported interface or dataset was changed. Moved code was moved verbatim.

The refactor was applied on top of an uncommitted working tree: 75 modified tracked files and 28 untracked paths over commit `ed969a4`. That work was kept intact; nothing was discarded, reverted or deleted. The source map and module conventions are in [ARCHITECTURE.md §4](../ARCHITECTURE.md#4-source-tree-and-ownership).

How behavior preservation was checked:

- **Verbatim moves.** A script moved whole top-level statements. A separate check confirmed that all 60 top-level statements of the split modules are identical to the originals. The only edit allowed was adding `export ` where a declaration became shared between modules. TypeScript's `noUnusedLocals` confirms the rewritten import lists are exact.
- **No visual change.** Stylesheets are bundled in module-evaluation order, so moving imports could silently change the cascade. After every step the production CSS was rebuilt and compared byte-for-byte with the pre-refactor build.
- **Tests after each step.** The non-UI suites (real DuckDB-WASM pipeline, POS, GL, master data, evidence) ran after the SQL change. The 35 jsdom UI tests ran after each component split.
- **Build output.** One new 96-byte shared chunk, `sql-quoting-*.js`, is preloaded together with the lazily loaded engine, GL and accounting chunks. The entry chunk and the requests made at startup are unchanged.

Not verified: browser rendering and interaction. As in earlier reviews, no browser was available; jsdom tests do not measure layout.
